# Volumetric Clouds MVP (three.js / WebGL2)

Генерация 3D density volume (uint8, 0 — чистый воздух, 255 — максимум) для объёмных облаков
и интерактивный просмотр с метеорадаром.

## Запуск

`start.bat` (нужен Python) — поднимет `http://localhost:8080/` и откроет браузер.
ES-модули не грузятся по `file://`, поэтому нужен локальный сервер. three.js r160 лежит в `vendor/`, интернет не нужен.

## Что умеет

- До 4 слоёв облачности, не пересекающихся по вертикали (перекрытие исправляется автоматически).
  Параметры слоя: нижняя граница, мин. толщина, диапазон толщины, количество 1–8 октантов, тип.
- 14 типов: Ac, Sc, Cu humilis/mediocris/congestus/towering, Cb calvus/incus, Anvil Head,
  Ns, Ns flat, As, St, Ci.
- Видимость — оптическая (МДВ): дымка по Кошмидеру (`β = 3.912 / V`), плотность дымки экспоненциально спадает с высотой.
- Солнце: азимут, высота, анимация. Небо, цвет солнца, окружающий свет и дымка считаются по одной физической
  модели атмосферы (однократное рассеяние Рэлея и Ми), поэтому согласованы на любой высоте солнца, включая закат.
  Тени облаков на земле и друг на друге — из того же объёма.
- Камеры «Над облаками» и «Под облаками» для проверки вида с обеих сторон; процедурный ландшафт (поля, межи, леса).
- Метеорадар (миникарта): отражаемость ≈ интеграл d² по столбу → dBZ, палитра NWS, полярные бины,
  развёртка, позиция и сектор обзора камеры. Клик по радару переносит точку обзора.
- Пресеты, камеры (обзор, с земли, сверху, сбоку, крупно, в облаке), seed — генерация детерминирована.

## Смежные density volume и плавная склейка

- Мир делится на сетку **зон** (1×1, 2×1, 1×2, 2×2, 3×1, 3×3), у каждой свои слои: типы, высоты, количество.
  Каждая зона генерируется отдельным проходом как собственный density volume. Зона выбирается кнопкой
  в панели или Shift+кликом по радару. Кнопка «Слои → во все зоны» копирует слои выбранной зоны во все остальные.
- По вертикали объём автоматически делится на **два яруса** (нижний и верхний) со своим вертикальным
  разрешением. Граница проходит по самому большому промежутку между слоями, а если его нет — посередине.
- **Шва нет по построению**: поле облаков считается одной глобальной функцией в мировых координатах.
  Одинаковые слои (тип + номер среди слоёв этого типа) всех зон — одна популяция облаков с общей сеткой
  ячеек и seed. Ярусы перекрываются на один срез, на границе оба считают одно и то же.
- **Переход** шириной «Ширина перехода между зонами» (км) вокруг каждой границы — билинейная гладкая смесь
  параметров 2×2 соседних зон:
  - покрытие перетекает (например, Sc 2/8 → 8/8);
  - высоты нижней границы и толщина перетекают (переход по вертикали, например Cu humilis → Cu congestus);
  - разные типы взаимно гаснут через покрытие, а их высоты при этом сходятся к высотам соседнего слоя
    того же семейства;
  - присутствие облака решается в центре его ячейки, поэтому в полосе перехода облака целиком появляются
    или исчезают, а не режутся.
- Для рендера зоны лежат в общем атласе (сторона до 1024 текселей, при сетке 3×3 разрешение зоны уменьшается):
  raymarching, тени и радар идут через границы зон без швов.
- Пресеты «Зоны: …» показывают холодный фронт Cu → Cb → Ns, переход покрытия, переход высот и сетку 2×2.

**Экспорт** («Скачать volume зоны») — файл `.cvol`:
`[uint32 LE длина JSON][JSON-заголовок][данные ярусов подряд]`. Данные — uint8 плотность 0..255;
внутри яруса x меняется быстрее всего, затем z (с севера на юг), затем высота (снизу вверх).
В заголовке: положение и размер зоны в км, число вокселей, высоты и число срезов каждого яруса, слои зоны.

## Как устроено

| Файл | Что внутри |
|---|---|
| `js/cloudTypes.js` | Таблица типов: параметры формы + значения слоя по умолчанию, пресеты |
| `js/shaders.js` | `genFrag` — генерация объёма; `detailFrag` — тайловая текстура детализации; `cloudFrag` — raymarching; небо, земля, радар |
| `js/main.js` | Рендер, генерация по срезам, радар, атмосфера, камеры |
| `js/ui.js` | Панель управления |

**Генерация** идёт на GPU: фрагментный шейдер рендерит каждый горизонтальный срез в `WebGL3DRenderTarget` (R8).
Срезы считаются по несколько за кадр, интерфейс при этом не замирает.
Вертикальный диапазон объёма подстраивается под слои, поэтому вертикальное и горизонтальное разрешение разные
(например, 83 м по горизонтали и 45 м по вертикали).

Объём хранится в RG8: R — плотность, G — характер края (1 — кучевые клубы, 0 — волокна и рваные края).
Параметры типов подобраны по фото-референсам из `../images/refs`, там же описано, что из каждого взято.

- **cumulo** (Cu, Sc, Ac, Cb): ячейки на джиттер-сетке. Наличие ячейки зависит от количества октантов,
  крупномасштабной кластеризации и гряд. Размер облака выводится из толщины слоя и пропорций типа:
  `R = H / (2·aspect)`. Распределение размеров такое: много мелких облаков и мало крупных.
  Облако состоит из тонкого тела вращения (плоское основание, сужение, купол, наковальня со сносом по ветру)
  и 12–20 пузырей-башенок, которые и задают бугристый силуэт. Соседние облака сглаженно сливаются в массивы.
  Под Sc лежит сплошная палуба. Поверх всего — смещение поверхности шумом Ворлея (три октавы) и fbm.
  Координаты перед построением искажаются низкочастотным шумом, а пузыри — эллипсоиды разной формы,
  поэтому вершины выглядят как неправильные доли, а не как «попкорн» из шаров.
- **Наковальня Cb**: плато чуть ниже верха слоя с волнистостью, над ядром — купол (overshooting top) до верха слоя,
  волокнистая текстура вдоль ветра. Снизу свисают mammatus — «мешки» ~1 км шириной и до 550 м высотой.
- **sheet** (St, As, Ns): лист с маской покрытия по порогу fbm, переменной толщиной и рваной нижней границей.
- **cirrus**: fbm, вытянутый вдоль ветра, с доменным искажением.

**Основание кучевых**: у каждого облака свой уровень конденсации (не ниже нижней границы слоя),
дно — сглаженное пересечение с плоскостью (плоское, но без острого ребра), мягкий переход плотности и лёгкая волнистость.

**Рендер**: raymarching по боксу объёма. Шаг растёт с расстоянием, пустота пропускается.
Для теней — 6 выборок оптической толщи до солнца, многократное рассеяние приближено октавами,
фазовая функция — двойная Хеньи-Гринштейн, окружающий свет затеняется облаком сверху.
Края эродируются тайловым шумом 128³ (две октавы) по схеме Horizon Zero Dawn:
инвертированный Ворлей там, где G≈1 (клубы), и fbm там, где G≈0 (волокна).
Первые выборки к солнцу тоже идут с эрозией, поэтому мелкие клубы отбрасывают тени друг на друга.
Powder-эффект и боковая затенённость (4 выборки по горизонтали) затемняют впадины между клубами и между mammatus.
Тройная фазовая функция даёт серебристую кайму при контровом свете.

**Земля**: вытянутые поля, поделённые на полосы разных культур, рядки посевов, дороги и лесополосы по межам,
пятна травы, массивы леса с кронами. Мелкие детали (от 0.3 м до 15 м) плавно гаснут с расстоянием по fwidth.

## Метеомодель облакообразования

`meteo.html` — облака из метеоданных: профиль температуры и влажности, прогрев, инверсии, крупномасштабный подъём
(циклон, фронты). Модель (`js/meteo/model.js`, описание — `../docs/meteo_model.md`):

- метод частицы → уровень конденсации, CAPE/CIN, уровень равновесия → конвективные облака (Cu humilis … Cb incus);
- подъём слоёв на w·τ + схема Сандквиста → слоистые облака (St, Sc, Ac, As, Ns, Ci);
- идеализированный циклон с тёплым и холодным фронтами → карта облачности 2000×2000 км и вертикальный разрез;
- видимость: туман, дымка, осадки.

Выход — те же слои, что задаются вручную. Кнопка «Открыть в 3D» передаёт их генератору: `index.html?scene=<JSON>`.
