# Volumetric Clouds 2 — фотореализм (mvp_clouds2)

Экспериментальная версия генератора объёмных облаков. Цель — **фотореализм уровня фото-референсов** в реальном времени. База — форк стабильного `mvp_clouds` (см. [`../mvp_clouds`](../mvp_clouds)); коды двух приложений не пересекаются: это независимые копии, правки переносятся вручную отдельными коммитами с пометкой «backport».

Трекер задач: локальный Redmine, проект «Volumetric Clouds 2 — фотореализм (mvp_clouds2)», задачи #74–#126 (эпики E0–E8). Методика приёмки — вики проекта «Методика тестирования».

## Отличия от mvp_clouds

- Рендер будет активно ломаться и меняться — `mvp_clouds` остаётся стабильным MVP на GitHub Pages.
- Появляется **стенд разработки**: эталонные сцены, детерминированный «режим съёмки», автоскриншоты, метрики похожести, профили качества.
- Дальше по плану: TAA с пониженным разрешением, многооктавная детализация, многократное рассеяние, перистые 2.5D-слоем, цвет и камера, адверсальное тестирование.

## Как запускать

ES-модули не грузятся по `file://` — нужен локальный сервер:

```
start.bat            # http://localhost:8081/  (порт 8081, чтобы не конфликтовать с mvp_clouds на 8080)
```

или вручную:

```
python -m http.server 8081
```

## Режим съёмки (стенд, #76)

Детерминированный кадр для эталонных сравнений: `index.html?shot=<сцена>&view=<0..4>`
(сцены и ракурсы — `test/scenes.json`, см. `test/make_scenes.mjs`).

- Буфер кадра фиксирован 1600×900 и не зависит от окна; время и динамика заморожены.
- Готовность: `window.__shotReady === true` (ошибка — `window.__shotError`).
- Порог готовности — < 5 с после загрузки страницы; компиляция тяжёлого шейдера `genFrag`
  (~37 с на ANGLE/D3D11, один раз) оплачивается прогревом при загрузке модуля.
- Два снимка подряд после готовности побайтно равны: после settle-кадров цикл рендера
  останавливается, буфер канваса сохраняется (`preserveDrawingBuffer`).
- Проверка: `node test/shot_check.mjs [url] [сцена] [view]` — один кадр;
  `node test/shot_run.mjs [url]` — все 15 кадров (3 сцены × 5 ракурсов) с отчётом в `test/shots/report.json`.

## Структура

- `index.html` — приложение (панель настроек, радар, зоны, экспорт)
- `meteo.html` — метеомодель облакообразования
- `js/` — генерация density volume, шейдеры, рендер, UI, ландшафт, share-ссылки
- `vendor/` — three.js и OrbitControls (локальная копия, без CDN)
- `data/` — данные ландшафта (городская застройка)
- `docs/` — стенд: эталонные сцены, автоскриншоты, метрики (появится в E0)

## Правила версий

Как в `mvp_clouds`: при изменении любого `js/*.js` или `style.css` поднимайте `?v=` в `index.html` (во всех строках импортов, в теге `main.js` и у `style.css`). Версии `mvp_clouds` и `mvp_clouds2` независимы.
